# AGENTS.md

Static-export Next.js 15 (App Router) single-page site for Omkar Shubham Garden, deployed to GitHub Pages at `/shubham-omkar`. TypeScript strict, Tailwind CSS 4 (CSS-first config in `app/globals.css` via `@import "tailwindcss"`, no `tailwind.config.*`), React 19.

## Commands

- `npm run dev` — dev server (no basePath)
- `npm run lint` — ESLint
- `npx tsc --noEmit` — typecheck (no script defined)
- `npm run build` — static export to `out/`; production builds default to basePath `/shubham-omkar`
- No test framework exists. Verify changes with lint + typecheck + build.
- Deploy: automatic on push to `main` via `.github/workflows/deploy.yml`.

## BasePath rules (critical)

- Production builds serve under GitHub Pages project path `/shubham-omkar`. Any hardcoded `/images/...` or absolute link breaks on Pages.
- All asset/video/image/href paths must go through `sitePath()` from `lib/site.ts` (handles external URLs, data URIs, and anchors). Follow the existing pattern in components — everything currently uses it.
- Do not remove from `next.config.ts`: `output: 'export'`, `images.unoptimized`, `trailingSlash: true`, `basePath`/`assetPrefix`. Server features (API routes, SSR) are unavailable by design.

## i18n

Four languages (`en`, `hi`, `mr`, `kn`) switched client-side; no per-language routes. Two dictionaries:

- `lib/i18n.ts` — nested content copy, accessed as `t('section.key')`
- `lib/uiTranslations.ts` — flat UI strings, accessed as `t('ui.key')`

Both consumed through `useLanguage()` in `components/LanguageContext.tsx`. English is the fallback for missing keys, but add new copy to **all four** dictionaries. Language persists in localStorage key `osg_lang`; provider renders `'en'` on server and swaps after mount to avoid hydration mismatch — keep this pattern when touching language state.

## Structure

- Single page: `app/page.tsx` assembles all sections as client components from `components/`.
- `app/layout.tsx` owns SEO metadata and JSON-LD; venue facts (phones, address, capacities) are real business data — preserve exactly.
- `public/images/` holds WebP-only photos plus hero video (WebM+MP4); new assets should be referenced with `sitePath()`.
- Design/content spec used to build the site: `omkar-shubham-redesign-prompt-v2.md` (historical reference for design intent).

## Component & asset conventions (added 2026-08)

- **Stat pairs**: any number+label pairing must use `<Stat>` (`components/Stat.tsx`) — value and label as two block children in a flex-col with a gap. Never render `{value}{label}` inline; this bug shipped to production once.
- **Image pipeline**: WebP is the only committed raster format. Resize before encoding with ffmpeg, cap long edge at 1200px for gallery/space tiles (1600px full-bleed hero/story, 600px logo/thumbnails), quality 82, strip metadata. Example:
  `ffmpeg -i in.jpg -map_metadata -1 -vf "scale='min(1200,iw)':'min(1200,ih)':force_original_aspect_ratio=decrease" -c:v libwebp -q:v 82 out.webp`
- **Image manifest is required**: `lib/image-manifest.json` holds real pixel dimensions, generated by `node scripts/generate-image-manifest.mjs` (needs ffprobe). Run it after ANY image add/resize — the gallery build fails loudly if a filename is missing from it.
- **Gallery** uses justified layout via the `justified-layout` npm package (v4 API: returns `{boxes, containerHeight}` — NOT v2's `containers`), measured against real container width via debounced ResizeObserver. Keep lightbox/hover behavior intact when touching it.
- **Space-tab images** render as stacked layers cross-faded by opacity (never swap one `<img>` src) + cache prewarmed on mount + base64 blur-ups from `lib/spacePlaceholders.ts`. This prevents the stale-image-under-new-label bug.
- **Language gate morph**: header language buttons carry `data-lang-control`; `FirstVisitLanguageGate` FLIP-animates its chosen button onto that target (WAAPI) and pulses it gold. If you add another header language entry point, give it the same attribute or the morph loses its landing target.
